# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A Python 3.12 + `textual` + `rich` TUI prototype of Slay the Spire (Generation 1 as content baseline). Local single-player, menu-driven, save/load capable. Not a GUI or server project.

## Commands

All commands use `uv`:

```bash
uv sync --dev                                          # install dependencies
uv run slay-the-spire new                              # start new game
uv run slay-the-spire new --seed 5 --character ironclad
uv run slay-the-spire load --save-path saves/latest.json
uv run pytest                                          # run all tests
uv run pytest tests/use_cases/test_save_load.py        # run a single test file
uv run pytest tests/ -k "test_name"                   # run tests matching a name
uv build                                               # build wheel/sdist
uv run python scripts/generate_local_wiki.py           # regenerate docs/local_wiki/cards_and_relics.md
```

## Architecture

### Layer Overview

```
CLI (app/cli.py)
  └─> SessionState (app/session.py)  — game state, menu routing, cross-act flow
        ├─> use_cases/               — game operations (play_card, end_turn, enter_room, save/load, etc.)
        │     └─> domain/            — combat model, map generation, rewards, Hook system, status effects
        ├─> adapters/textual/        — SlayApp (Textual UI), MapWidget, textual_runner
        ├─> adapters/presentation/   — shared Rich renderables, combat/non-combat screens, inspect panels
        ├─> adapters/persistence/    — JsonFileSaveRepository (saves/latest.json)
        └─> content/                 — loaders, registries, typed definitions (CardDef, RelicDef, etc.)
```

### Key Files

- `app/session.py` — **central hub**: SessionState dataclass, all menu routing, cross-act transitions, rendering helpers. Treat this as ground truth for flow.
- `app/menu_definitions.py` — numbered menu definitions consumed by session and UI.
- `adapters/textual/slay_app.py` — full Textual App (compose, refresh, action handlers).
- `domain/` — combat resolution, Hook event system, map generation, reward generation.
- `ports/` — interfaces: `ContentProviderPort`, `InputPort`, `SaveRepository` (dependency inversion).

### Content System

- **Authoritative source**: `content/` (repo root) — edit only here.
- **Packaged copy**: `src/slay_the_spire/data/content/` — generated by `setup.py`'s custom `build_py` during `uv build`; never hand-edit or commit.
- At runtime, the app reads `content/` when running from the repo; the packaged copy is used only when installed as a wheel.
- Registries in `src/slay_the_spire/content/` parse JSON from `content/` and expose typed objects to the rest of the code.

### Save System

- Default save path: `saves/latest.json` (not committed).
- Current `schema_version`: **3**. If the save schema changes, update `save_game.py`, `load_game.py`, and related tests together.
- No backward-compatibility requirement for old saves in current development phase.

### Reference Materials

- `docs/reference/` — local reference data for development. **Development reference only**, not loaded at runtime.
  - `红色牌.json` — Ironclad card list reference.
  - `无色牌.json` — Colorless card list reference.
- When original game data is needed, check here first; use external Wiki only to supplement.

## Collaboration Rules

- Player-facing UI text (menus, events, card descriptions, effect labels) defaults to **Chinese**; code identifiers, commands, paths, and necessary proper nouns stay in their original language.
- When game design sources conflict, follow: **current codebase Gen-1 baseline + already-landed behavior** > Gen-2 materials > old design docs.
- `session.py`, `tests/`, and `content/` are the sources of truth — not design documents.

## Change Checklist

When adding/modifying:

| Change | Also check |
|---|---|
| New room type | Map content, use case/session routing, presentation layer, Textual layer |
| Boss reward or cross-act flow | Full chain: `boss → boss_chest → next act / victory` |
| New character, card, enemy, event, relic, or potion | Content registries, drop/pool entries, corresponding tests |
| New combat or boss reward | `domain/rewards/reward_generator.py`, `use_cases/apply_reward.py`, tests |
| Menu, render, or session routing | `tests/adapters/presentation/`, `tests/e2e/` |
| Textual UI | `tests/adapters/textual/test_slay_app.py` |
| Content registry or JSON structure | `tests/content/test_registry_validation.py` |
| Save structure | `tests/use_cases/test_save_load.py`, bump `schema_version` |

## Documentation Maintenance

After any code, content, command, flow, test baseline, or release change: update `README.md`. Update `AGENTS.md` only when collaboration constraints or repository factual entry points change.
